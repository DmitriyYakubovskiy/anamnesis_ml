# Эксперимент по статье

Источник: предоставленный PDF «Извлечение медицинских данных из электронных медицинских карт с помощью алгоритмов обработки естественного языка», А. В. Гусев, Р. Е. Новицкий, А. А. Ившин, Ю. С. Болдина, А. С. Штыков, А. С. Васильев (перевод статьи AD ALTA, с. 314–319).

Использованы идеи разных методов для разных задач, spaCy NER, линейной классификации с текстовыми признаками, небольших растущих minibatch, dropout и ограничения градиента. Это адаптация, а не точное воспроизведение статьи. В статье наборы существенно больше; её показатели нельзя переносить на наши 46 обучающих анамнезов. Медицинские словари, исправление опечаток и правила постановки диагноза не добавлялись: источник и координаты сохраняются, а правила требуют отдельной проверки.

## Протокол

Прежнее разбиение: train 46, validation 10, test 9. Train: true 26 / false 7 / null 13. Validation: true 5 / false 2 / null 3; 7 эталонных NER-фрагментов. Seed 42, 60 эпох spaCy; фиксированная сетка из четырёх линейных классификаторов. Веса классификатора, словарь и IDF считаются по train. Выбор эпохи и классификатора — только по validation. Тестовый файл не читался при обучении, подборе и проверке качества этого эксперимента.

На CPU обучение и выбор заняли около 76 секунд в данной среде; это не прогноз времени для другого компьютера. Предобученные веса не использовались. Python 3.12, spaCy 3.8.7, scikit-learn 1.7.2. Машиночитаемая сводка без текстов пациентов и ID: [article_validation_result.json](article_validation_result.json).

## Результаты лучшего состояния

| Метрика | Train, только диагностика | Validation |
| --- | ---: | ---: |
| NER exact character-span F1 | 0.6866 | 0.2000 |
| NER F1 символов сущностей | 0.9851 | 0.5393 |
| Классификатор macro-F1 | 1.0000 | 0.6869 |
| Классификатор accuracy | 1.0000 | 0.7000 |

NER: выбрана эпоха 44; validation TP=1, FP=2, FN=6, precision=0.3333, recall=0.1429. На train TP=23, FP=11, FN=10. У 9 из 33 train-фрагментов пришлось расширить границы в обучающей копии до границ токенов; оригинальные gold границы остались в оценке. Это отдельная проблема качества границ, а не основание исключать неудобные примеры.

Классификатор: выбран LinearSVC C=0.25. На validation F1 false=0.6667, true=0.7273, null=0.6667. Предсказаны false 1 / true 6 / null 3; постоянного ответа true больше нет. Простой ориентир «всегда true» для этой же validation имеет accuracy=0.5 и macro-F1=0.2222. Это ориентир, а не повторный запуск прежнего RuBERT.

NER распознаёт часть сущностей, но его полнота пока низкая. Разрыв train/validation и всего 10 validation анамнезов не позволяют считать результат устойчивым. На test улучшение не проверено. Следующий полезный шаг — расширить разметку, согласовать границы сущностей и добавить группировку по пациентам, если доступны patient ID; document_id не гарантирует независимость пациентов.

## Совместимость

Существующий transformer backend остаётся по умолчанию. У него изменены веса NER на sqrt inverse frequency, чтобы редкий B не получал чрезмерный перевес, и выбор checkpoint при одинаковом exact F1: сначала entity-token F1, затем validation loss. Основной F1 всегда приоритетен. Реальное качество обновлённого RuBERT в этом эксперименте не измерялось; цифры выше относятся к hybrid. Старые сохранённые модели можно оценивать прежними командами. LoRA, Qwen и файлы датасета не изменены.

## Воспроизведение

Из корня проекта:

```bash
pip install -r requirements-hybrid.txt
python ner_classifier/train.py --backend hybrid --epochs 60 --output runs/encoder_article_v1
python ner_classifier/evaluate.py --models runs/encoder_article_v1 --split validation --output runs/encoder_article_v1_validation
```

Train-диагностика и validation-диагностика сохраняются автоматически внутри папок задач. После окончательного выбора настроек можно один раз оценить test:

```bash
python ner_classifier/evaluate.py --models runs/encoder_article_v1 --split test --output runs/encoder_article_v1_test
```

Повторный подбор по результатам test превратит его в дополнительную validation. Для нового эксперимента выбирайте новый output.
