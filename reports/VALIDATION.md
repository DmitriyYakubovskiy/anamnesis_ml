# Обновление обучения NER/классификатора — 26 октября 2026

36 unit/integration тестов прошли на Python 3.12, torch 2.8.0+cpu, transformers 4.57.1 и accelerate 1.10.1. Предупреждение Trainer о порядке mtime файлов не повлияло на результат.

Дополнительно проверены:

- отдельные веса классов по train: inverse frequency для O/B/I с исключением -100, и классов классификатора; отсутствующие классы и отключение балансировки;
- взвешенная cross-entropy совпадает с PyTorch, поддерживает backward и не даёт NaN при полностью игнорируемых labels;
- metric callback корректно обрабатывает padding и argmax IDs; collapse в один класс даёт ожидаемый macro-F1; all-O даёт NER F1=0;
- checkpoint selection использует validation F1: отдельный интеграционный тест задаёт F1 0.9, затем 0.1 и подтверждает выбор первого checkpoint и фактическую загрузку его весов;
- exact NER F1 использует исходные символьные границы, а не расширенные до токенов; token-aligned F1 хранится отдельно;
- пересечение train/validation по ID, документам или нормализованному тексту отклоняется;
- сквозной CPU smoke: обе encoder-модели обучаются, вычисляют F1, сохраняют class_weights и train/validation диагностику. test.jsonl во время обучения намеренно заменён невалидным JSON — обучение завершается без чтения этого файла;
- явная оценка train помечается diagnostic_only; итоговая оценка test по-прежнему доступна через --split test;
- полный прежний smoke для LoRA, merge, Qwen full SFT, baseline и compare продолжает проходить.

Исходный JSON, все подготовленные выборки, manifest и схема не менялись. Пользовательские веса encoder_v1 не перезаписываются; нужно отдельное обучение encoder_v2. Улучшение качества на реальном наборе ещё не измерено: тесты проверяют реализацию, не гарантируют F1.

Manifest трёх вариантов совпадает. Все ID присутствуют в одном split; document_id между split не пересекается. Группировка также удерживает одинаковые нормализованные тексты вместе. Patient_id в экспорте отсутствует: разделение по пациентам не подтверждено.

## Проверки кода

24 unit/integration теста прошли:

- точные типы, false/0/null, исключение непроверенного значения и непроверенного результата;
- корректные Unicode-координаты, запрет пересечений одной метки, безопасные имена колонок;
- воспроизводимость разбиения при изменении порядка входных записей, отсутствие утечки источников/идентичных текстов;
- строгий JSON без автоматического ремонта; отсутствие ключа не приравнивается к null;
- exact span F1 и BIO, коллизии внутри одного токена;
- answer-only mask, padding и запрет обрезания целевого ответа;
- mock LM Studio HTTP endpoint: успешные и сломанные ответы, сохранение метрик и ошибок, весь тест остаётся в знаменателе.

Все Python-файлы прошли синтаксический разбор.

## Сквозной CPU smoke test

Временные случайные крошечные Qwen3 и BERT, синтетические записи, по одному optimizer step:

- обучение и сохранение NER;
- обучение и сохранение классификатора;
- оценка NER + классификатора с файлами метрик/предсказаний;
- обучение LoRA, загрузка adapter и генеративная оценка;
- merge в исходную базу; logits adapter/base и merged совпадают с atol=1e-5;
- полный SFT Qwen;
- оценка plain Qwen без обучения;
- compare.py на совпадающих исходнике/split/ID.

Это smoke test инфраструктуры: случайные веса не дают осмысленного качества. Его нулевые/случайные метрики не являются результатами на медицинском датасете. Временные веса не включены в архив.

- Qwen/Qwen3-4B-Instruct-2507: все 65 обучающих представлений помещаются в 4096, максимум 1181 токен с prompt+ответом; chat template и маска ответа проверены.
